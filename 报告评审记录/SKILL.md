# 研究报告HTML转打印PDF

这是“报告评审记录”目录的可复用入口，支持V2.2／V2.3类单文件信息卡（同一骨架）。收到“把今天报告转成PDF”等请求时，先找指定日期目录，读取标题识别公司，按此说明执行。

## 用户已验收的标准

- A4竖版、每份**6页以内**；少于6页不补空页。允许缩小字体、收紧留白、调整分页。
- **保留原HTML的卡片、配色、评分十格、关卡格子、纯度条、风险底色、表格和层级。不得改成纯文字双栏、摘录摘要或把整页截图缩印。**
- 前面研究内容全部保留。展开同敞口中的整体背景、评分依据、纯度估计、终端映射、技术情景等折叠内容；推断和待核层也保留原性质标识。
- 打印版删除末尾“评分规则与口径”和“数据与资料来源”整个部分。证据底稿只保留日期、标题、正文，删除引用链接标记；普通文字链接保留文字。其他位置的引用编号可保留为原文标记。
- 顶部打印按钮、开关、临时试算输入等屏幕操作控件可以隐藏；固定B/C分数、计算公式及必要价格输入必须保留。
- 不修改原始HTML，不纠正其事实、分数或结论，不偷偷删“看起来冗余”的正文，不替评审作裁决。发现研究问题另记，不在打印转换中改稿。
- PDF是“已生成”，不等于操盘手已纸质打印或已读完；不要直接调用纸质打印机。

## 本目录在统一工作区中的位置

- 本目录是 `产业信息卡skill/` 的打印评审区，不是独立文件夹。
- daily push 的 HTML、推送正文、运行底稿直接写在 `YYYYMMDD/`；V2.2／V2.3 卡的六页 PDF 也放同目录。
- `inbox/` 放其他研究员的单文件 HTML；`outbox/` 放通用 HTML 转出的 PDF。
- 统一入口：`scripts/convert-any.sh`。它会自动识别 V2.2／V2.3 卡（六页流程）和普通 HTML（通用 A4 流程）。

```sh
# 某一天的全部 HTML
bash scripts/convert-any.sh --dir YYYYMMDD

# 单张 V2.2／V2.3 卡或普通 HTML
bash scripts/convert-any.sh path/to/report.html

# 其他研究员的 HTML（inbox → outbox）
bash scripts/convert-any.sh --inbox
```

## 运行资源

优先用桌面应用的`load_workspace_dependencies`定位Node/Python依赖，再运行同目录脚本：

```sh
node scripts/html-report-to-pdf.mjs --dir /absolute/path/to/报告评审记录/YYYYMMDD
```

也可只转换指定文件：

```sh
node scripts/html-report-to-pdf.mjs /absolute/path/to/report.html
```

输出默认放输入HTML同目录，命名为`公司名-首次评审打印版-YYYYMMDD.pdf`。多个同公司同日版本需分别指定输出目录或先调整输出命名，不能无意覆盖不同版本。临时PDF、检查记录和截图放该日`.制作/`。

脚本依赖Playwright、本地Chromium/Chrome和Python的pypdf；默认适配本机Codex捆绑运行时。迁移机器时可设置`REPORT_RUNTIME`、`REPORT_PLAYWRIGHT`、`REPORT_PYTHON`、`REPORT_CHROME`为实际路径，不要求安装固定版本。CSS见[scripts/print-report.css](./scripts/print-report.css)，不要复制昨天的公司、日期或价格进脚本。

使用可用PDF制作工具时遵守其操作标记和渲染检查要求。若系统要求文件写入或启动浏览器权限，按实际错误申请；不反复询问已经确定的版式偏好。

## 排版关键点

1. 加载原HTML及其全部最终CSS，另加**仅打印生效**的CSS。保留背景色，启用`printBackground`和精确颜色输出。
2. 标题与总分并排；B/C两栏；同行表保留原三列及图形。长标题允许换行，避免把总分挤出页边。
3. 时间轴若把多个事件放在同一个不可跨页网格中，将“日期＋事件”拆成逐对打印容器，保留内容和视觉，避免第一页半页空白。
4. 同行表头跨页重复，单行尽量不拆；分节可以跨页。优先压缩卡片内外边距、表格padding、行距和字号，不能用固定高度/overflow:hidden裁掉内容。
5. 节点冲动分需独立留右侧空间；同时缩其宽度及字号，防止分数压住答案。证据日期和正文保持清楚对齐。
6. 脚本从较大打印比例尝试至0.80，满足6页即停。这是适配起点，不是视觉验收。仍超页时修复不必要留白、网格、行高、重复表头问题；不得无限缩到不可读，也不能擅删正文。若内容量确实无法同时兼顾，报告具体阻碍并请求调整。

## 必须完成的检查

- 页数：用pypdf实际数页，不能凭浏览器滚动长度猜。
- 内容：六节研究正文仍存在；折叠区已展开；规则与来源已删除；证据底稿没有引用链接；输入HTML的SHA256前后相同。
- 图形：总分条、阶段格、纯度条及颜色仍可见，不被“压缩”转换成散落数字。
- 逐页渲染成PNG，查看每一页或足够清晰的总览，放大检查密集表格、节点分数、首尾行。确认无横向裁切、叠字、空白整页、孤立标题、缺字、尾部内容丢失。
- 检查来源尾章确实删除，同时未误删最后一节证据。对不认识的HTML结构先检查映射，脚本报错不能靠删除该节绕过。
- 页数合格后，只因新改动或发现问题才重复生成。最终交付一个可点击PDF，并简述公司和页数；生成PDF不意味着已进行内容评审。

## 完成边界

本流程只转换打印副本与检查排版。评审裁决、信息卡规范改版、自动日更、纸质打印及Git提交分别依用户请求进行。文件生成不自动授权推送GitHub。
