# 产业信息卡 Version2.3：每日推送执行入口

本文件是入口。执行前先读本文件，再按需读 `references/`；**每次交付前必须读 `references/preflight-checklist.md`**。业务基准为 `references/original/信息卡-Version2.3-执行规范.md`；执行细则以 `references/execution-spec-checklist.md`、`references/scoring-and-timeline.md`、`references/render-and-naming.md`、`references/screening-and-resonance.md` 为准。V2.3 与 V2.2 细则冲突时，按本文件「规则优先级」处理。

## 0. 一句话

先判产业敞口，再选最正宗标的，最后才打分。**B＋C 只是数值准入，产业判断必须另有话说。** 每个敞口只交付一个自包含 HTML；过不了准入就不出卡、不进推送，如实报告全市场没有合适标的，绝不下调标准凑数。

## 1. 角色、边界与跟踪分离

- **研究员（领航员）**：敞口定义、证据搜集、纯度估计、下跌归因、未来节点、评分与比较、HTML 交付。
- **操盘手（用户）**：技术面核验、仓位、交易与退出。卡片不写仓位、止损或买卖指令。
- **本 skill 只出报告，不维护长期跟踪状态。** 不记录 take／pass 结果，不维护持仓，不做盘中跟踪；后续跟踪由外部机制承接。
- 卡面可保留一行中性状态：`推送状态：新推；本 skill 不维护长期跟踪，后续跟踪由外部机制承接。`
- 推送正文末尾是否保留 take／pass 表态请求，由 `config.example.yaml` 的 `take_pass_prompt` 控制；默认保留，因为外部跟踪机制可直接消费这句话。本 skill 不保存回复。
- 卡片内不得出现免责声明、仓位建议、「不构成投资建议」、历史版本对话或 take／pass 记录；页脚只留：`价格参照由研究员主观选择，技术面由操盘手核验`。

## 2. 两种模式

| 模式 | 触发 | 是否允许出未过准入的卡 | 交付 |
| --- | --- | --- | --- |
| `daily_push` | 08:00／09:00／10:00 定时任务，无用户点名 | **不允许**。未过线只在内部记录，不出卡、不进推送 | 单文件 HTML＋推送正文 |
| `named_research` | 用户点名个股或敞口 | 允许，但必须写明未过哪一项，不得称已入池 | 单文件 HTML（通常不出 PNG） |

`daily_push` 是默认模式；本包主要服务于它。`named_research` 沿用同一套规范，只是准入可以不过线。

## 3. 每日三档推送（08:00／09:00／10:00）

**时区：Asia/Shanghai。每次运行只产出一张卡；三次运行相互独立，不得复用同一敞口／主标的。** 如果执行环境只能调度一次，改为 08:00 主扫描，09:00／10:00 增量扫描；不要在一次运行里硬凑三张卡。

| 班次 | 职责 | 无合格标的时 |
| --- | --- | --- |
| 08:00 主扫描 | 全市场重新检索，建立当日候选池，最多推 1 张 | `本轮全市场未检索到符合准入的产业敞口。`＋最接近的被否决候选（≤3 个） |
| 09:00 增量 | 只找与 08:00 **不同**的合格敞口；读 08:00 输出与 `{{state_dir}}/pushed-index.json`（本工作区 `报告评审记录/.state/pushed-index.json`） | `本轮全市场未检索到新的符合准入产业敞口。`＋08:00 已推标的（如有） |
| 10:00 增量 | 同 09:00，不得重复 08:00／09:00 | 同 09:00 |

若配置 `no_new_policy: silence`，09:00／10:00 无新增时只输出一行：`暂无值得关注信息`。默认 `report`，因为用户要求明确知道全市场有没有合适标的。

**去重**：同一「敞口＋主标的」在 `dedupe_days`（默认 20 个自然日）内不重复推送；出现实质新事件需要更新时，标题与正文必须写「更新」并说明变化，不能假装新推。去重索引只是幂等记录，不是跟踪机制。

## 4. 每次运行的固定顺序

1. **读环境**：读本文件、`references/daily-push.md`、`references/preflight-checklist.md`、`references/scoring-and-timeline.md`；读 `config.yaml`（若不存在则读 `config.example.yaml`）与 `{{state_dir}}/pushed-index.json`（若存在；本工作区 `报告评审记录/.state/pushed-index.json`）。
2. **锁报告基准**：报告日、取价日（报告日前最近一个已收盘交易日）、班次、模式、输出目录。90 天＝报告日及后 89 个自然日，实算。
3. **交易日历核对**：按沪深交易所公告核对报告日、取价日与 90 天窗口内的交易日；**不读取、不依赖任何外部金融日历仓库**。取价日回退到最近一个已收盘交易日；无法确认时写「未取得」，不推测。
4. **建候选池**：先从 **60／120／250 交易日跌幅榜**建池，逐只算区间涨跌幅＋最大回撤；再定义敞口、查清下跌原因；再建 90 天节点地图并分级；只保留「跌幅榜＋S/A 级节点」共振候选。记录漏斗：跌幅榜候选 N → 敞口可定义 M → 下跌原因可查 L → S/A 节点 K → 纯度可算 J → 过准入 P。详见 `references/screening-and-resonance.md`。
5. **产业四件事（先做完再打分）**：①开篇产业主升命题（驱动／成立条件／主要矛盾／主标的承接）；②经营下滑归因（下降读数→原因→对主张的影响→证据/缺口）；③终端反推（份额→制造主体→供应关系→本敞口收入/利润承接，并比较利润环节）；④技术重要性判定（触发才展开，不触发就删除模块）。
6. **锁敞口比较约定**：敞口边界（含必须排除的邻近业务）、本次积极变化、期间、收入口径、证据口径五项先定。
7. **纯度三情景**：未单列也要推算，低／中／高＋中枢，参数逐项标来源或「研究假设」；禁用相邻板块占比、±误差、置信区间。03 表按中枢真实排序。
8. **五关与 C**：①故事②订单③收入④主营利润⑤毛利率改善；C 五档序数，禁止概率映射。公司整体数据只作背景或解释拖累。
9. **B 与总分**：R＝(有效压力位−收盘)÷(收盘−有效支撑位)，两侧锚点都必须取日线最近一次被量能测试过的位置；原精度判档。B 栏依据写六字段：类别｜价位｜位置日期｜当时量能｜被测试次数｜测试方式。写不出测试记录→B「未取得」、不生成总分。总分始终 B＋C。
10. **节点**：逐个写 `事件 → 本敞口可观察变量 → 主标的已有业务承接`；须同时满足有关、有桥、有时点、有用途；多跳缺桥直接删除，不降分占位。政策节点用状态标签、不评买入冲动。
11. **准入与出卡**：三条全过才出卡——①未确认杀逻辑；②B≥3 且 C≥3；③B＋C≥7。**均线只作行情事实记录，不作准入、打分、降级或「降为观察」依据，也不得新设趋势软门槛。**
12. **复制骨架出 HTML**：只替换占位符，不改结构、CSS、类名；删除全部 `<!-- -->` 注释；跑 `references/preflight-checklist.md` 全部阻断项；写推送正文与内部底稿。

## 4.5 跌幅榜 × 90 天现象级节点（daily_push 硬门槛）

用户 2026-11-10 明确：**先从 60／120／250 交易日跌幅榜找股票，查清下跌原因；未来 90 天必须有一个现象级兑现节点；两者共振才是好交易。** 这不是加分项，是 daily_push 的候选门槛。

- **跌幅榜**：60／120／250 交易日；同时算区间收盘涨跌幅、区间最大回撤、相对基准跌幅（行业指数优先，沪深300/中证全指兜底）；分窗口排序、不混算；窗口不足写「不存在」；默认剔除 ST／*ST、上市不足窗口、长期停牌、流动性过低。
- **下跌原因**：每只候选写 `下跌读数 → 触发事件 → 杀估值／杀业绩／杀逻辑（主次） → 证据 → 可解释性 → 可剥离性 → 最乐观那天能否定义`。确认杀逻辑→淘汰；找不到原因→写「尚未查明」，不得编。
- **节点分级**：S＝硬节点＋公司专属＋日期确定＋直接改变利润/价格/配额；A＝硬节点＋日期确定＋间接影响，或高确定性软节点＋公司专属订单/价格/客户事件；B＝行业级固定日历数据，只能辅助；C＝一般软节点，只调进度，不作兑现节点。
- **daily_push 至少要有 S 或 A 级节点**；只有 B/C 级节点，不出卡、不推送。
- **出货窗口四问**：谁付钱？哪个数字变好？为什么节点后市场愿意给更高价？什么结果会让节点失效？答不出，不是现象级。
- **共振排序**：节点质量 ＞ 跌幅可解释/可剥离 ＞ B/C ＞ 纯度。强共振＝跌幅榜＋S 节点＋B≥4＋C≥4；中共振＝跌幅榜＋A 节点＋B≥3＋C≥3。
- **卡片多写两行**：①跌幅读数：60/120/250 交易日绝对涨跌幅＋相对基准跌幅＋最大回撤；②出货窗口：S/A 节点日期＋谁付钱＋哪个数字变好＋更高价理由。没有则不出 daily_push 卡。

完整口径、分级表、无合格文案见 `references/screening-and-resonance.md`。

## 5. 硬准入与评分（不可改）

- **准入三条**：未确认杀逻辑；B≥3 且 C≥3；B＋C≥7。均线不在准入内（生菜 2026-11-04「MA5和MA10这个规矩以后去掉，不要了」）。
- **B 固定公式**：`R=(前高−参考收盘)/(参考收盘−支撑)`；未四舍五入判档：R<1→1，1≤R<2→2，2≤R<3→3，3≤R<4→4，R≥4→5。R 显示两位小数。
- **B 锚点新规**：分子＝有效压力位−现价，分母＝现价−有效支撑位；两侧都取「日线最近一次被量能测试过的位置」，同一取价日、同一复权口径。单日最高／最低、未测试过的单根均线、整数关口不得进入公式。锚点不合格→B「未取得」、不生成总分；不得先算 R 再补说明。
- **锚点量化判据（V2.3定稿）**：放量≥1.5×前20日均量、最近120个交易日、±1%价格带、**同一位置至少2次有效测试**（不同交易日、间隔≥5交易日）、取价A保守（支撑/压力都取带下沿）；只有1次测试只作观察位，不进入R，daily_push不得用1次测试锚点。备选 `anchor_profile: legacy_proposal`（1.5×/≥1次/B对称，仅历史复核）或 `strict`（2.0×/≥2次/A）。默认 `v2_3`。
- **赔率虚高**：支撑距现价过近（如不足5%）或分母过小时，在 R 旁标「赔率虚高·分母 X 元·支撑距现价 Y%」，只作风险提示，不降 B 档。
- **C 五档**：1 缺少有效线索；2 已有改善线索；3 变化相对可信；4 变化已经发生；5 已发生＋第二曲线。按最高完整满足档评分。禁止 30%/40%/50% 先验、胜率、贝叶斯后验或「判断值」式概率替代品。
- **H 只作标签**：H＝(收盘÷52周最高−1)×100%，不打分、不替前高。
- **总分**：只 B＋C；A、D/E、H、关卡、纯度、节点冲动都不计分。分数不是胜率，不产生仓位。
- **下跌主因**：先杀逻辑，再杀业绩，再杀估值；允许主次混合，必须写一句具体事实。确认杀逻辑的标的不作主动推荐。
- **最早证伪日**：能给确切日期就给 `YYYY-MM-DD`；查不到确切日就标「待确认（软节点）」并写清能证伪什么，不得用区间或「未取到」含糊代过。

## 6. 开篇标签：封闭白名单

位置：公司标题、代码之后，观点摘要之前；容器 `.opening-labels`；顺序固定，同类最多一条，条件不成立整块删除，不留空、不写「暂无」。

1. **下跌主因**（`.cause-label`）——每篇必有，写杀估值／杀业绩／杀逻辑及主次。
2. **短期下跌主因**（`.short-cause`）——仅明确事件驱动下跌时出现，须有公开日与相对走势依据。
3. **政策依赖度强**（`.pill.policy-dependency`，暗红）——仅未来获利前提明显依赖政策时出现，全卡最多一条；必须答全三问。
4. **技术迭代中**（`.pill.technology-label`，紫色）——仅 §2.4 触发时出现。
5. 机会类型、可展望程度（`.pill.blue`）——沿用既有分类词，可合并成一条。

禁止自造「核心约束」「风险等级」「政策敏感度」「重点关注」等同义标签。政策标签四条准入（A1 归属／A2 依赖／A3 可定位／A4 可观测）与七条排除（E1—E7）见 `execution-spec-checklist.md` §25；三问（政策身份、强度与方向、监控成本）缺一不得打标签。政策不是加分项、不自动扣 B/C，但必须进入 C 的支持／反证。**V2.3 已将强度三档、监控成本四字段、政策筛查表正式收录（规范 §5.6.1—5.6.3），交付说明不再标「本地增补」。**

## 7. 节点、证据与来源

- **节点四条件**：有关、有桥、有时点、有用途。只保留：事件名、回答什么问题、最可能答案、核心证据、一行复核含义、买入冲动分（1—10，不计分）。不要求恰好三个，不用未知节点凑数。
- **政策节点**：不评买入冲动，用 `政策约束／政策支持／政策双向 · 不评买入冲动`；核心证据含文件名＋发文机关＋文号（或注明无文号）＋最早公开信号日＋条款位置；复核行写监控成本四字段＋档位＋周均核查次数。
- **90 天**：报告日及后 89 个自然日；日期性质必须写清（实际公告／预约披露／公司计划／惯例推算／研究员观察窗口）；不把季末或 12-31 当自动发生日。
- **证据分层**：事实／推断／传闻待核实必须可分辨；推断与传闻放默认关闭的开关层；评分与必要答案在使用处可见。
- **来源**：每个来源有唯一 ID、可跳转；一手来源尽量精确到分钟，查不到写「原始发布时间未查到分钟级」；同一消息多平台转载不算多条独立证据；检索摘要不能冒充已读全文。
- **禁止**：用模型算出的收入情景反过来证明订单、收入或 C4；用公司整体数据顶替窄敞口；把未来节点插进历史证据轴。

## 8. HTML 交付契约

- **单文件、自包含**：内联 CSS／原生 JS；不加外部脚本、外部字体、CDN、图片或联网脚本；来源链接可联网打开，正文、折叠、开关、试算离线可用。
- **文件名**：`<敞口>-<主标的>-产业信息卡-YYYY-MM-DD.html`，日期取报告日；同日同标的多次出卡追加 `-NN`。
- **输出目录**：由 `config.yaml` 的 `output_dir` 决定；本工作区写 `报告评审记录/YYYYMMDD/`（日期子目录用 YYYYMMDD，卡文件名仍用 YYYY-MM-DD）；分发版默认 `outputs/YYYY-MM-DD/`。
- **骨架**：`assets/skeleton-template.html` 是唯一骨架。复制后只替换占位符；`REPEAT` 块按实际条数展开或删除；条件块 0 或 1 次，不适用就整块删除；最终文件不得残留 `{{…}}`、`<!--`、`-->` 或 REPEAT 标记。
- **首屏**：产业主升命题＋下滑归因（如有）＋标签＋总分＋四个速览＋准入检查行；准入检查行只写 B／C 是否达门槛，不写均线判定。
- **跌幅读数**：03 第一列或 06 证据写 60/120/250 交易日区间涨跌幅＋最大回撤；不足写「不存在」；不得只写“跌幅较大”。
- **出货窗口**：首屏或 01 写 S/A 节点日期、谁付钱、哪个数字变好、为什么更高价；没有 S/A 节点不出 daily_push 卡。
- **十格条**：前 B 格浅蓝 `value-b`，接着 C 格深蓝 `value-c`，其余 `value-empty`；B 标签 `grid-column:1/{{B_LABEL_END}}`（`B_LABEL_END=B+1`），C 标签 `grid-column:{{B_LABEL_END}}/{{C_LABEL_END}}`（`C_LABEL_END=B+C+1`）。C 阶梯给当前档 `class="active"`。
- **B/C 五格刻度**：`{{B_TICKS}}`／`{{C_TICKS}}` 各放 5 个 `<i>`，得分前 N 个加 `class="on"`。
- **head**：`<title>` 与 `<meta name="description">` 必须填真实内容，不得留占位符或空值。title＝`产业信息卡 YYYY-MM-DD｜敞口 · 公司 代码`；meta description＝1—2 句，含报告日、标的、B＋C 与是否过线。
- **状态行**：在 `<footer>` 前单列一行 `<p class="note track-status">推送状态：新推；本 skill 不维护长期跟踪，后续跟踪由外部机制承接。</p>`。
- **页脚**：只留 `价格参照由研究员主观选择，技术面由操盘手核验`。
- **不出 PNG**：每日推送只交付 HTML；用户点名要图时才按 `render-and-naming.md` 出 PNG。
- **打印 PDF**：本 skill 只出 HTML；打印副本由统一工作区的 `报告评审记录/scripts/convert-any.sh` 处理（V2.2 卡自动六页，其他 HTML 通用 A4），不在出卡流程里重排。
- **不能写文件时**：在回复中直接返回完整 HTML（代码块）与推送正文，说明「未落盘」；不得截断 HTML，不得只给摘要。
- **卡片内不写**：免责声明、改版史、「原报告／原卡／上一版」、概率列、先验、胜率、take／pass 状态、持仓、聊天背景。

## 9. 交付前自检（最低必须）

完整清单见 `references/preflight-checklist.md`；以下任一项不过，不得交付：

- [ ] 准入三条全过；未确认杀逻辑；没有把未过线样本包装成推荐。
- [ ] 首屏有四段式产业主升命题；有回落时概述有 1—2 句归因；03 有终端映射与利润去向；技术触发判断有记录，触发时 04 展开、未触发时不留空表。
- [ ] 标签只白名单六类、顺序正确、同类最多一条、无自造、无空位；政策标签三问齐全。
- [ ] 纯度三情景＋中枢＋参数来源；03 按中枢排序；没有相邻板块占比顶替。
- [ ] 五关与 C 只判本敞口；C 无概率映射。
- [ ] B 两侧锚点均为量能测试过的位置；六字段齐全；R／B／总分三处一致；赔率虚高只标注不降档。
- [ ] 节点四条件全过；无多跳缺桥；政策节点不评买入冲动。
- [ ] 90 天首尾实算正确；head title／meta 已填；`{{`／`<!--` 计数为 0；六节齐全；来源 ID 唯一可跳转。
- [ ] 无「MA5＞MA10」「均线不过即观察」等判定；无免责声明；页脚正确。
- [ ] 若环境可跑浏览器：`scrollWidth ≤ 1160`，桌面／窄屏无遮挡或整页横向溢出。

有 Python 时，交付前运行：

```bash
python3 scripts/validate_card.py "{{output_dir}}/YYYYMMDD/<文件名>.html"
```

脚本只做结构与一致性检查，**通过脚本不等于通过语义检查**；仍须逐项过 `preflight-checklist.md`。

## 10. 失败、降级与无合格标的

- **没有合格敞口**：如实报告，不得下调标准。08:00 用 `本轮全市场未检索到符合准入的产业敞口。`；09:00／10:00 用 `本轮全市场未检索到新的符合准入产业敞口。`。可列最多 3 个最接近的被否决候选及理由码（C 不足／B 锚点未取得／B＋C<7／已确认杀逻辑／纯度不可推算／证据不足／数据源不可用），正文仍≤5 行。
- **跌幅榜有候选、但 90 天内没有 S/A 级节点**：不出卡；推送 `本轮全市场未检索到「跌幅榜＋90天现象级节点」共振的合格敞口。`＋最多 3 个被否决候选，注明「无S/A节点」。
- **有 S/A 节点、但不在跌幅榜或 B/C 不过线**：不出卡；推送 `本轮有节点候选，但没有跌幅榜与赔率同时成立的敞口。`
- **跌幅与节点不共振**：只进内部观察，不出卡、不推送；`named_research` 可呈现，但须标「非 daily_push」。
- **候选有、但证据不足以完成 B/C**：视为未过线，不出卡；在内部底稿写清缺哪一项。不得用「待核验」标签掩盖未完成的核心比较。
- **数据源／网络不可用**：写「未取得」，不推测；若关键证据缺失导致无法判 B/C，淘汰该候选。若全市场数据源都不可用，报告 `本轮全市场未检索到符合准入的产业敞口（数据源不可用，未取得）。`
- **交易日历不可用**：取价日回退到最近一个已收盘交易日；仍无法确认时写「未取得」，不推测。**不再核对任何外部金融日历仓库。**
- **锚点取不到**：B 标「未取得」、不生成总分；不得默认 B2 或 B5。
- **重复推送**：读 `{{state_dir}}/pushed-index.json`；同一敞口＋主标的在 `dedupe_days` 内不再推；有新事件要更新时标「更新」并说明变化。
- **用户明确修改优先**：用户当前指令 > 本 skill > 原始规范 > 历史卡片。任何本地增补（政策强度分档、监控成本字段、政策筛查表、锚点量化判据）在交付说明标「本地增补」，不得冒充规范原文。
