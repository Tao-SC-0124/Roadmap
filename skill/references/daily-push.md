# 每日推送编排（daily_push）

本文件只解决「每天 08:00／09:00／10:00 怎么稳定跑出报告」。研究规则仍以 `SKILL.md` 与三份现行 reference 为准；本文件不新增分数、不改变准入。

## 1. 运行参数

默认值见 `config.example.yaml`：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `timezone` | Asia/Shanghai | 所有班次与日期按北京时间 |
| `push_times` | 08:00 / 09:00 / 10:00 | 三次独立调用；每次最多 1 张卡 |
| `cards_per_run` | 1 | 不得多出；三次合计最多 3 张 |
| `take_pass_prompt` | true | 推送末尾是否加 take/pass 请求；不影响卡片 |
| `dedupe_days` | 20 | 同一「敞口＋主标的」去重窗口；有新事件可标「更新」 |
| `no_new_policy` | report | 09:00／10:00 无新增时：`report` 报「未检索到新的」；`silence` 只输出「暂无值得关注信息」 |
| `output_dir` | outputs | HTML、推送文本、运行日志；本工作区为 `正式卡` |
| `pdf_output_dir` | outputs/pdf | PDF输出；本工作区为 `待打印PDF` |
| `date_folder_format` | YYYY-MM-DD | 日期子目录格式；本工作区为 `YYYYMMDD` |
| `state_dir` | outputs/state | 去重索引目录；本工作区为 `报告评审记录/.state` |
| `anchor_profile` | v2_3 | `v2_3`＝1.5×／≥2次／取价A／±1%；`legacy_proposal`＝1.5×／≥1次／取价B（仅历史复核）；`strict`＝2.0×／≥2次／取价A |

**每次运行先读配置：优先 `config.yaml`，不存在则读 `config.example.yaml`；两者都没有时用默认值，并在运行日志注明「使用默认配置」。**

## 2. 一次运行的十五步

1. **确定班次与报告日**：北京时间；报告日＝运行日；取价日＝报告日前最近一个已收盘交易日（遇周末／节假日回退）。记录到运行日志。
2. **读今日已有产物**：`{{output_dir}}/YYYYMMDD/` 下的 HTML、`push-*.txt`、`run-*.md`；读 `{{state_dir}}/pushed-index.json`。本工作区为 `正式卡/YYYYMMDD/` 与 `报告评审记录/.state/pushed-index.json`。确认本班次不得重复的敞口／主标的。
3. **交易日历核对**：按沪深交易所公告核对报告日、取价日与 90 天窗口内的交易日；取价日回退到最近一个已收盘交易日。**不读取、不依赖任何外部金融日历仓库**；无法确认时写「未取得」，不推测。
4. **建跌幅榜候选池**（见 §3）：分别取 60／120／250 交易日跌幅榜，逐只算区间收盘涨跌幅＋最大回撤＋相对基准跌幅（行业指数优先，沪深300/中证全指兜底）；去重、剔除 ST／*ST／上市不足窗口／长期停牌／流动性过低；目标 20—40 个候选，记录每只挂在哪个窗口、哪个跌幅更大。
5. **逐个候选过「敞口可定义」**：能写清具体产品／环节、必须排除的邻近业务、本次积极变化、期间、收入口径、证据口径。写不清的淘汰。
6. **逐个候选查「下跌原因」**：写 `下跌读数 → 触发事件 → 杀估值／杀业绩／杀逻辑（主次） → 证据 → 可解释性 → 可剥离性 → 最乐观那天能否定义`。确认杀逻辑淘汰；找不到原因写「尚未查明」，不得编故事。
7. **逐个候选建 90 天节点地图并分级**：按 S／A／B／C 分级；daily_push 至少要有 1 个 S 或 A 级节点；节点须过四条件（有关／有桥／有时点／有用途），并回答出货四问（谁付钱／哪个数字变好／为什么更高价／什么信号失效）。
8. **只保留「跌幅榜＋S/A 节点」共振候选**：无 S/A 节点→不出卡；只有节点不在跌幅榜→named_research，不进 daily_push；跌幅与节点不共振→内部观察，不出卡、不推送。
9. **逐个候选过「纯度可算」**：用公司披露或至少一种可追溯推算法给出低／中／高＋中枢；算不出的淘汰（除非能给出有业务边界的宽情景；仍算不出则淘汰）。
10. **逐个候选过「五关／C 可判」**：至少能判到第三关或明确停在第二关；C 必须有同敞口证据。只有公司整体数据的，标「公司口径·非本敞口」并保守降档。
11. **逐个候选算 B**：按 `scoring-and-timeline.md` §1.1；两侧锚点都必须量能测试过；V2.3默认1.5×／120交易日／±1%／同一位置至少2次有效测试／取价A保守；写六字段。只有1次测试只作观察位，不进入R；写不出→B「未取得」，该候选淘汰（daily_push 不生成无总分的卡）。
12. **准入筛选**：未确认杀逻辑；B≥3；C≥3；B＋C≥7。全过才进入候选排序。
13. **排序与定主标的**：节点质量 ＞ 跌幅可解释/可剥离 ＞ B/C ＞ 纯度；同一敞口内再按「纯度 × 兑现进度（五关）」排序。主标的必须能回答「为什么不是公认龙头」（3—5 家同环节横向对比）。**不许因为某只票便宜就把它当一个敞口。**
14. **出卡**：复制 `assets/skeleton-template.html`，替换全部占位符；删除注释与 REPEAT 标记；卡片必须写「跌幅读数」与「出货窗口」；跑 `preflight-checklist.md`；写 HTML 到 `{{output_dir}}/YYYYMMDD/`（本工作区 `正式卡/YYYYMMDD/`）。
15. **写推送正文、运行日志、去重索引**：正文≤5 行（不含 take/pass 行）；日志记录跌幅窗口与最大回撤、下跌原因、节点分级、出货窗口、候选池漏斗、被否决候选及理由码、关键来源、耗时；索引追加本次推送。

## 3. 候选池口径（全市场怎么扫）

「全市场」默认指沪深北 A 股。**daily_push 默认剔除 ST／*ST、上市不足窗口、长期停牌、流动性过低**；`named_research` 可例外，但须说明。候选来源以跌幅榜为主、事件驱动为节点来源，**不要只看看涨幅榜**：

1. **60／120／250 交易日跌幅榜**：每个窗口单独排序，逐只算区间收盘涨跌幅＋区间最大回撤；去重后保留「跌因可解释、可剥离、最乐观那天能定义」的候选。跌幅只提供候选，不直接决定推荐。
2. **事件驱动节点**：业绩预告／快报、定期报告、股东会、解禁、政策实施日、配额核发、涨价函、订单／中标、客户认证、产品量产、行业数据固定发布日。每个节点按 `screening-and-resonance.md` 分 S／A／B／C；daily_push 至少要有 S/A。
3. **产业景气与价格数据**：产品涨价、价差扩大、库存拐点、开工率、出口数据、月度行业数据；优先找「价格已经动、报表还没体现」的环节。
4. **公司公告与订单**：中标、框架协议、产能投产、客户认证、定增／回购、业绩预告；区分签署／公开／实施日期。
5. **政策与标准**：准入、配额、环保、补贴、目录、实施日；政策只作线索，节点与日期须一手核验。
6. **终端与供应链**：终端品牌份额、整机厂排期、供应商认证、单机价值量；从销售端倒推，不从概念股名单开始。

**常用来源（按需，不限于此）**：

| 类型 | 入口 | 用法 |
| --- | --- | --- |
| 公司公告 | 巨潮资讯 `cninfo.com.cn`；上交所 `sse.com.cn`；深交所 `szse.cn`；北交所 `bse.cn` | 一手公告、定期报告、业绩说明会、股东会 |
| 行情与估值 | 东方财富 `quote.eastmoney.com`／`data.eastmoney.com`；同花顺 `10jqka.com.cn`；腾讯行情 `qt.gtimg.cn` | 收盘价、成交量、52周高低、换手、市值、PE |
| 行业数据 | 国家统计局 `stats.gov.cn`；海关总署 `customs.gov.cn`；发改委 `ndrc.gov.cn`；工信部 `miit.gov.cn`；行业协会官网 | 产量、价格、出口、开工率、政策 |
| 政策原文 | 国务院 `gov.cn`；各部委官网；地方政府官网 | 文件名、发文机关、文号、签署／公开／施行日 |
| 交易日历 | 沪深交易所公告 | T+N、节假日、最后交易日；**不读取外部金融日历仓库** |

来源只是入口；**公告原文 > 交易所 > 公司官网 > 协会 > 主流财经媒体 > 研报转载**。研报与媒体只能作交叉验证，不能单独支撑订单、收入或 C4。

**候选池漏斗**（写进运行日志）：

```
60/120/250 交易日跌幅榜候选 N（分窗口标注）
→ 敞口可定义 M（淘汰：业务太杂／无法排除邻近业务／只有概念）
→ 下跌原因可查 L（淘汰：确认杀逻辑／尚未查明且影响 C）
→ S/A 级 90 天节点 K（淘汰：无 S/A 节点／只有 C 级软节点）
→ 纯度可算 J（淘汰：无任何可追溯证据／只能拿相邻板块占比）
→ 五关/C 可判 I（淘汰：只有公司整体数据且无法保守定档）
→ B 可算 H（淘汰：锚点未取得／未经量能测试）
→ 过准入 P（未确认杀逻辑、B≥3、C≥3、B+C≥7）
```

**时间预算**：单班次研究深度优先于数量。若候选太多，先按「在跌幅榜 + 有 S/A 节点 + 纯度可算 + 证据可追溯」排序，取前 10—15 个做深研；其余只记漏斗，不硬凑。**宁可少推，不可降标准。**

**禁止**：跳过 60/120/250 交易日跌幅榜直接选股；用当天涨幅榜直接当敞口；把 C 级软节点当兑现节点；用行业分类（Wind／申万／中信）当同敞口依据；用「能力可复用」当供应链证据；用模型算出的收入情景反过来证明订单或 C4。

## 4. 三次班次怎么区分

- **08:00**：完整跑 60／120／250 交易日跌幅榜，建节点地图，允许从零建立候选池。若推了一张卡，把「敞口＋主标的＋报告日＋班次」写入索引。
- **09:00**：先读 08:00 的卡与索引；只找**不同敞口或不同主标的**，且必须同样是「跌幅榜＋S/A 节点」共振。若 08:00 没有合格标的，09:00 仍可重新扫，但必须说明「与 08:00 相比新增了什么证据」。
- **10:00**：同 09:00；不得重复 08:00／09:00。
- 同日三次合计最多 3 张；不足 3 张是正常结果，不得为了凑数降低准入。
- 若某班次发现 08:00 的卡有硬错误（锚点不合格、纯度口径错、标签违规），不要静默改分；在运行日志标「08:00 卡需修订」，按新证据重出并用 `-02` 文件名，推送正文说明「修订」。

## 6. 推送正文模板

### 6.1 有合格标的

```
<一句核心结论，句内不带数字>
（空行）
<正文≤5行：敞口、主标的、为什么现在、最早证伪日、主要风险>
请回 take 或 pass；若 take，请同时告知准备操作的标的与代码。
```

- 第一行是判断句，不是标题；句内不出现数字（数字放正文或 HTML）。
- 正文不超过 5 行；其余全部进 HTML。
- take/pass 行固定另起一行；若 `take_pass_prompt: false`，删除该行。
- 不写免责声明、不写「仅供参考」、不写「不构成投资建议」。

### 6.2 08:00 无合格标的

```
本轮全市场未检索到符合准入的产业敞口。
（空行）
候选池 N 个均未过线；最接近的被否决候选：A（C 不足）、B（B 锚点未取得）、C（已确认杀逻辑）。
```

- 被否决候选最多 3 个；理由码从「C 不足／B 锚点未取得／B＋C<7／已确认杀逻辑／纯度不可推算／证据不足／数据源不可用」中选。
- 若候选池为 0，第二行写 `候选池 0 个；检索范围与缺口见运行日志。`，不要编造候选。

### 6.3 09:00／10:00 无新增

默认 `report`：

```
本轮全市场未检索到新的符合准入产业敞口。
（空行）
08:00 已推：XXX；其余候选未过线。
```

若 `no_new_policy: silence`，整条只输出：

```
暂无值得关注信息
```

不写发送时间、不列跟踪清单、不写说明。

## 7. 失败与降级

| 情形 | 处理 |
| --- | --- |
| 交易日历不可用 | 取价日回退到最近可用交易日；仍无法确认时写「未取得」；不读取任何外部金融日历仓库 |
| 行情接口不可用 | 取价日回退到最近可用收盘；仍不可用则本班次不推，报告「数据源不可用，未取得」 |
| 跌幅榜有候选、但无 S/A 节点 | 不出卡；推送「本轮全市场未检索到『跌幅榜＋90天现象级节点』共振的合格敞口。」 |
| 有 S/A 节点、但不在跌幅榜或 B/C 不过线 | 不出卡；推送「本轮有节点候选，但没有跌幅榜与赔率同时成立的敞口。」 |
| 只有 C 级软节点 | 不作兑现节点；不出 daily_push 卡 |
| 确认杀逻辑 | 直接淘汰；不得进 daily_push |
| 某候选关键证据缺失 | 淘汰该候选；不生成卡；在漏斗与理由码记录 |
| B 锚点写不出六字段 | 淘汰；不得默认 B2／B5 |
| 纯度只能拿相邻板块占比 | 淘汰；不得入 03 表 |
| 卡片结构校验失败 | 修复后重跑；不得「口头说已修」 |
| 运行环境不能写文件 | 在回复中返回完整 HTML（代码块）＋推送正文，说明「未落盘」；不得截断 |
| 时间不够完成全部检查 | 推「未检索到符合准入」，不要推半成品 |

## 8. 质量闸门（推送前最后 60 秒）

- 候选来自 60／120／250 交易日跌幅榜？区间涨跌幅＋最大回撤＋相对基准跌幅写了？挂在哪个窗口写清了？
- 下跌原因分类、可解释性、可剥离性、最乐观那天能否定义，写清了？
- 至少 1 个 S/A 级 90 天节点？节点四条件＋出货四问都答了？
- 跌幅与节点共振？排序按节点质量＞跌幅可解释/可剥离＞B/C＞纯度？
- 准入三条全过？未确认杀逻辑？
- 卡内 B／C／总分三处一致？十格条格数正确？
- B 锚点六字段齐全？两侧都量能测试过？V2.3默认1.5×/120日/≥2次/A/±1%，没有用1次测试锚点？
- 纯度三情景＋中枢＋参数来源？03 按中枢排序？
- 标签白名单、顺序、政策三问？没有自造标签？
- 节点四条件？没有多跳缺桥？政策节点没评冲动？
- `{{`、`<!--`、`-->` 计数为 0？head title／meta 已填？
- 删除免责声明／概率／先验／take-pass 状态／持仓？
- 推送正文第一行不带数字、正文≤5 行？无合格时文案正确？
- 去重索引已写？运行日志已写？

任何一项不确定，按「不推」处理。
