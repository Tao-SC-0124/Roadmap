# 交付前阻断项清单（每次必读 · V2.3 适用）

> **V2.3 适用**：业务基准为 `references/original/信息卡-Version2.3-执行规范.md`；本清单同时覆盖 V2.2 产业四件事与 V2.3 跌幅榜、节点、锚点、打印检查。冲突时 V2.3 规范优先。

**任一项不通过＝不得交付。** 本清单是 `execution-spec-checklist.md` §21、§25.7 与规范 §12 的执行版；遇到规则不清时回查原文，不要凭记忆补规则。

## A. 准入与总分

- [ ] 准入三条同时满足：①未确认杀逻辑；②B≥3 且 C≥3；③B＋C≥7。
- [ ] 均线只作行情事实记录；全文（含隐藏层、JSON、meta、交付说明）无「MA5＞MA10」「均线不过即观察」「均线未过门槛」等判定，也没有新设趋势软门槛。
- [ ] 指定研究若未过线，明确写「未过准入」及未过哪一项；没有称已入池。
- [ ] 总分只 B＋C；A／D／E／H／关卡／纯度／节点冲动都不计入。
- [ ] B 按未四舍五入的 R 判档；R 显示两位；没有主观改档；赔率虚高只标注不降档。
- [ ] B 锚点两侧同一标准、同一取价日、同一复权口径；分子＝有效压力位−现价，分母＝现价−有效支撑位。
- [ ] B 栏依据六字段齐全：类别｜价位｜位置日期｜当时量能｜被测试次数｜测试方式。
- [ ] 锚点未经量能测试／写不出测试记录 → B 写「未取得」、不点亮刻度、不生成总分；没有先算 R 再补说明。
- [ ] 同一位置至少1次有效测试；1次标「1次测试」，2次以上标「多次测试」；不因次数改B档。
- [ ] 量化判据：放量≥1.5×前20日均量、最近120交易日、±1%价格带、取价A保守（支撑/压力都取带下沿）。
- [ ] C 是序数五档；全文（含隐藏层、aria、脚本、meta、JSON）无先验 30/40/50%、胜率、贝叶斯后验、「判断值」式概率替代品。
- [ ] H＝(收盘÷52周最高−1)×100%，只作标签；没有用所选前高替身。

## B. 产业四件事（V2.2／V2.3）

- [ ] 首屏 `.thesis` 有四段式主升命题：敞口 → 驱动 → 成立条件 → 主要矛盾 → 主标的承接。缺一不合格。
- [ ] 证据不足时明确写「目前不足以支持主升判断」及原因；没有为模板强行看多。
- [ ] 有营收／本敞口收入／销量／售价／吨毛利／归母／扣非回落时，概述有 1—2 句归因：下降读数 → 原因 → 对主张的影响 → 证据/缺口。
- [ ] 没有把增速放缓写成绝对下降；没有把销量下降写成营收下降；没有用公司整体毛利率判窄敞口吨毛利；没有用税项解释毛利。
- [ ] 03 有终端映射（前 5—10 家、口径一致、匿名身份保留推断）与利润环节比较；缺数据处说明范围与缺口，不凑名次、不硬排。
- [ ] 技术重要性每份都判断过并留内部记录；触发才贴「技术迭代中」并展开 04；不触发则 04 只留 D/E、无空技术表。
- [ ] 04 技术观点是判断句（谁、在哪种情景、凭什么占优），附证据与「改变观点的信号」；没有用「更值得比较」等研究动作代替观点。
- [ ] 技术模块不计分、不自动提高 C、不新增仓位／止损。

## C. 敞口、纯度与同敞口

- [ ] 打分前已锁五项敞口比较约定：敞口边界（含排除项）、本次积极变化、期间、收入口径、证据口径。
- [ ] 03 每行纯度有数值＋「%」＋「推算值／披露值」＋报告期；没有「未取得／未披露／—」终值。
- [ ] 纯度低／中／高＋中枢由参数实算；参数逐项标来源或「研究假设」；没有 ±X 个百分点、置信区间或误差保证。
- [ ] 03 按中枢真实降序；范围共用 0—100% 尺；区间重叠不硬判优劣。
- [ ] 没有用相邻板块占比（消费电子／智能硬件／精密零组件／电子工艺装备等）直接充当纯度。
- [ ] 每行有入选依据层级（a 公司披露／b 一手产业证据／c 研报交叉验证）；仅 c 不作单独依据；仅行业分类／能力复用不入表。
- [ ] 每行标注所处环节；跨环节不合并排序；证据不足者移出表、表外单列、不参与排序与出分。
- [ ] 五关与 C 只判本敞口；只有公司整体数据时标「公司口径·非本敞口」并保守降档；没有用最成熟子线掩盖其他子线。

## D. 标签与政策

- [ ] 开篇标签只用白名单六类：下跌主因／短期下跌主因／政策依赖度强／技术迭代中／机会类型／可展望程度。
- [ ] 顺序固定；同类最多一条；没有「核心约束」「风险等级」「政策敏感度」「重点关注」等自造类别；条件不成立整块删除，不留空、不写「暂无」。
- [ ] 下跌主因每篇必有；性质与主次清楚；确认杀逻辑的标的不作主动推荐。
- [ ] 短期下跌主因仅在明确事件驱动时出现；有公开日与同区间相对走势依据；没有用时间先后冒充因果。
- [ ] 政策标签四条准入（A1 归属／A2 依赖／A3 可定位／A4 可观测）全过；七条排除（E1—E7）一条未命中。
- [ ] 政策标签三问齐全：①文件名＋发文机关＋文号（或注明无文号）＋最早公开信号日＋条款位置；②强度（强／中）与方向（约束／支持／双向）；③监控成本四字段（指标｜发布主体与载体｜频率｜获取方式｜时滞）＋档位＋周均核查次数。
- [ ] 政策节点不评买入冲动；复核行是监控成本，不是「持续跟踪」「密切关注」。
- [ ] 政策筛查表覆盖材料中全部政策，结论落「打标签／仅作 01 节点／仅进 06 证据／排除」四类并带理由码；随运行日志附出，不上卡面。
- [ ] 没有把「消息已反应」写成「已充分定价」；只有公开事实时写「消息已公布」。
- [ ] 政策提示没有被技术段落替代；技术触发不等于政策依赖解除。
- [ ] 政策三问、监控成本、筛查表按V2.3规范§5.6执行；这三项已正式收录，不再标“本地增补”。

## E. 节点与时间轴

- [ ] 90 天＝报告日及后 89 个自然日，实算；首尾正确。
- [ ] 每个节点满足四条件：有关、有桥、有时点、有用途。
- [ ] 没有连续两个以上缺事实支持的商业环节；多跳缺桥已直接删除，没有降分占位。
- [ ] 节点只保留：事件名、回答什么问题、最可能答案、核心证据、一行复核含义、买入冲动分（1—10）。
- [ ] 日期性质写清：实际公告／预约披露／公司计划／惯例推算／研究员观察窗口；没有把季末或 12-31 当自动发生日；没有虚构单日。
- [ ] 行业级节点明确只验证行业变量，不冒充公司订单证据。
- [ ] 政策节点有状态标签（政策约束／政策支持／政策双向 · 不评买入冲动）与监控成本。
- [ ] 没有凑数会议、重复节点、未知节点。

## F. 证据与来源

- [ ] 证据按时间排序，只留改变判断的已发生事实；没有把未来节点插进历史轴。
- [ ] 事实／推断／传闻可分辨；推断与传闻在默认关闭的开关层；评分与必要答案在使用处可见。
- [ ] 来源 ID 唯一、可跳转；点击来源能展开父折叠。
- [ ] 一手来源尽量精确到分钟；查不到写「原始发布时间未查到分钟级」；转载标明转载，不冒充原始来源。
- [ ] 同一消息多平台转载没有算成多条独立证据；检索摘要没有冒充已读全文。
- [ ] 政策事实的签署日／官网公开日／施行日分列，没有合并；最早公开信号日出现在 06 首条。

## K. 跌幅榜与节点共振（daily_push）

- [ ] 候选来自 60／120／250 **交易日**跌幅榜；明确挂在哪个窗口、哪个跌幅更大；绝对跌幅、最大回撤、相对基准跌幅（行业或沪深300）都写了，并注明所用指数。
- [ ] 每个窗口都写了区间收盘涨跌幅＋区间最大回撤；两者分开，不混算；窗口不足写「不存在」。
- [ ] 默认剔除 ST／*ST、上市不足窗口、长期停牌、流动性过低；named_research 例外已说明。
- [ ] 每只候选写了下跌原因：杀估值／杀业绩／杀逻辑（主次）、证据、可解释性、可剥离性、最乐观那天能否定义。
- [ ] 确认杀逻辑的标的没有进入 daily_push；找不到原因的写了「尚未查明」，没有编故事。
- [ ] 至少 1 个 S 或 A 级 90 天节点；B 级只作辅助，C 级软节点没有当兑现节点。
- [ ] 节点四条件（有关／有桥／有时点／有用途）全过；出货四问（谁付钱／哪个数字变好／为什么更高价／什么信号失效）全答。

- [ ] 03 第一列或 06 有「跌幅读数」：60/120/250 交易日绝对涨跌幅＋相对基准跌幅＋最大回撤。
- [ ] 跌幅与节点共振；排序按节点质量＞跌幅可解释/可剥离＞B/C＞纯度。

## J. 一键命令（环境支持时）

```bash
# 占位符与注释
grep -c '{{' card.html
grep -c '<!--' card.html

# head
grep -o '<title>[^<]*</title>' card.html
grep -o '<meta name="description"[^>]*>' card.html

# 结构计数
grep -o '<main' card.html | wc -l
grep -o '<header' card.html | wc -l
grep -o '<footer' card.html | wc -l

# 禁用词
grep -nE '免责声明|不构成投资建议|仅供参考|MA5＞MA10|均线不过即观察|先验概率|胜率|原报告|原卡|上一版' card.html

# 结构校验（可选）
python3 scripts/validate_card.py card.html
```

**脚本通过不等于语义通过。** 逐节点、逐公司、逐标签的语义检查仍须人工完成。
